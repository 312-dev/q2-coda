| The player's own TLS and decoders | [player-plan.md](player-plan.md) | A new player built from source, `q2player`, is replacing `hciplayer` ([player-plan.md](player-plan.md): phase 1 of 7 is done), which answers this item with current libraries; what follows is the in-place alternative, kept in case that work stops. `hciplayer` is MPlayer with its own static FFmpeg (3.0 by its banners, [player.md](player.md#what-it-is)) and OpenSSL 1.0.1 in a stripped 7.6 MB binary, which no library upgrade reaches. Patch it in place, as Q2 Muse already does: (1) a host-name check after the TLS handshake, done by payload code reading the peer certificate (days); (2) drop the formats it never needs from its built-in demuxer and decoder lists, so old code for obscure formats is unreachable (days); (3) redirect its FFmpeg entry points to the patched shared FFmpeg 4.2.x (weeks; each entry point must first be identified in the stripped binary). Replacing the player outright means rebuilding Shanling's glue (the command protocol `demo` uses, DSD and SACD, output routing, Tidal, AirPlay and DLNA queues, QQ Music decryption) and porting Q2 Muse's player patches to source: worth it only with Shanling's GPL source (requested); no Q2 GPL source is published (searched 2026-11-13), and the M1 Plus project above has notes on the same player |
