# The game engine

A small engine inside the UI payload for games drawn at the panel's refresh: a fixed 60 Hz step, a frame's input as one record, drawing straight into the screen's buffer inside the rects a step said changed, the Clicker's sounds, and sealed saves. It is `patch/engine.c` and `patch/engine.h`; `patch/engine_demo.c` is a scene that proves it and shows a game's four calls. Games (`patch/games.c`) is its page: the chooser lists the engine's games after its own (those `GAME_*` in `patch/peq.h` ships: none in this build, so Pop Stall is the first row), and the pause menu is Games' pop-up.

This page is the design, the measurements behind it, the API, the budgets and the libraries considered. The older games (Sudoku, Vortex, Solitaire, Snake) are in [internals: Games](internals.md#games) and do not use the engine.

## Where it runs

**In the payload, on demo's UI thread.** The alternative, a program of its own in the root filesystem that takes `/dev/fb0` as `q2video` does ([internals: Videos](internals.md#videos)) or a card game's ([Card apps](internals.md#card-apps)), was weighed and set aside:

| Question           | In the payload                                                                                  | A separate program                                                                                                         |
| ------------------ | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Sound under music  | The Clicker's route: q2player mixes the sound into the song ([Key Tone](internals.md#key-tone)) | None. The player holds the one PCM (`hw`, no `dmix`), so a second program cannot open it while a song plays                |
| The user's library | In reach (the music quiz reads the library database and drives the player)                      | Would need a protocol to demo for every query and every play                                                               |
| Input              | The wheel's own thread and speed, keys and touch, already decoded                               | demo must stay the reader and forward each event as a datagram (what card games do), a pass of the UI loop late            |
| Text and theme     | Inter and the theme's faces through stock's canvas                                              | Its own font rasteriser and font files                                                                                     |
| Memory             | The game's state on demo's heap (2 to 8 KB a game)                                              | A second process: its own libc mappings and stacks, some hundreds of KB next to the player on a device with no swap        |
| Smoothness         | One paint a refresh, paced by the flush thread's wait for vertical sync (measured below)        | The same pacing at best: it would pan `/dev/fb0` and wait for the same sync                                                |
| Size               | 7.6 KB of the payload for the engine and its demo (below)                                       | Payload room spared, but 225 KB is all the root filesystem has free, and the forwarding code would still be in the payload |

Nothing the separate program offers is needed, and it loses sound under music outright. The payload's limit is the cost, so each game has a byte budget ([Budgets](#budgets)).

## The panel

The screen is `lcd_h0209s`, 320 x 375 physical, shown turned as 375 x 320. Its mode is in `module_driver/lcd_h0209s.ko`'s `fb_videomode`: refresh 60, 320 x 375, margins 24 and 20 (horizontal), 12 and 16 (vertical), sync lengths 20 and 2. That is 384 x 405 clocks a frame, and at 60 Hz 9,331,200 Hz, the "9.3 MHz pixel clock" of [hardware](hardware.md). So **the refresh is 60 Hz and a frame is 16.67 ms.** `ENG_HZ` is that number. ponytail: this is the driver's stated mode, not a measurement of a panel; no Q2 was on hand to time `FBIO_WAITFORVSYNC`. `tools/q2remote.py profile` on a development Q2 would settle whether the real figure is a little off 60.

The path a frame takes is stock's ([internals: Night Shift](internals.md#night-shift) describes the same path): AWTK paints each changed rect into the screen's `lcd_mem` buffer (375 x 320, BGRA8888), `lcd_end_frame` hands the frame to the flush thread, which turns it onto the page of `/dev/fb0` not on screen, pans to it (`FBIOPAN_DISPLAY`) and waits for vertical sync (`FBIO_WAITFORVSYNC`; `soc_fb.ko` is loaded with `pan_display_sync=1`). The UI thread's next paint waits for that flush, so **while the picture changes every pass, the UI loop runs once a refresh**: the emulator shows it, where a sync is a 16 ms sleep and the demo scene flips every 17 ms ([In the emulator](#in-the-emulator)). ponytail: seen in the emulator and read from stock's flush path, not timed on a Q2. If a Q2's loop came round sooner than its panel, the loop below would still step by the clock (its second case), a frame now and then shown twice. The engine does not flip pages or wait for sync itself; it rides this.

## The frame loop

`eng_frame` is an AWTK timer of `ENG_TIMER_MS` (4), so it is due at every pass of the UI loop. Each pass it looks at the time since the last pass (stock's millisecond clock):

- **15 ms or more** (`ENG_SNAP_LO`): the pass followed a paint, so the gap is whole refreshes. It is rounded to the nearest count of them, one step each: 16 and 17 ms are both one step, 33 is two, at most `ENG_MAX_STEPS` (4); time beyond that is dropped, so a stall never becomes a burst.
- **less**: nothing was painted, the loop came round early. The time is added to what is owed (`acc`, in 1/60000 s) and a step is taken when a whole one is owed.
- **the timer's first pass** is a step whenever it comes, so a turn-based game answers a key on the next pass.

So on a Q2, where a pass is one refresh, a game steps exactly once per displayed frame and never 0 or 2 by the millisecond clock's rounding: motion is even, with no interpolation needed. A step is always 1/60 s of game time; a game never reads a clock.

After the steps, each rect the game marked (`eng_dirty`) is invalidated on the sheet. Stock paints each apart with the canvas clipped to it, and `games_paint` calls the game's `draw` once per rect through `eng_paint`. A step that marks nothing paints nothing.

`ringnav_sleep`'s idle sleep is off while the timer runs (`games_live`, `np_animating` in `patch/navigation.c`). A turn-based game (`ENG_STILL`) keeps the timer only after input and while its `step` returns 1; at rest there is no timer and the loop idles as on any page.

**Pausing.** The screen off or another window on top: `eng_frame` ends its timer and Games shows "Paused" (`engine_held`); Center or Play/Pause resumes. Return opens Games' menu (Continue, Quit). Either way `eng_hold` stops the timer, gives the wheel back to ticks and calls the game's `pause`, which is where a game saves. Held Return is Home, as everywhere.

**Nothing is allocated in a frame.** `eng_open` makes one `calloc` of the engine's record and the game's state (`size`), freed by `eng_close`. The payload's scratch holds one pointer (4 bytes).

## Measurements

All on the demo scene, build `--dev --new-player`.

### On MIPS

`test/patch.py` runs the built payload under Unicorn and counts the payload's instructions (stock's text drawing and the flush are mocked, so these are the engine's and the game's own):

| What                                                                | Instructions |
| ------------------------------------------------------------------- | ------------ |
| A frame's step (ball, paddle, the wheel turning), the dearest of 60 | 499          |
| That frame with its changed rects painted (2 to 5 rects)            | 61,511       |
| The whole sheet painted (375 x 290: the start, a pause, a resume)   | 703,036      |

The suite bounds each a little above what it measured (600, 70,000 and 780,000), so a change cannot quietly make a frame dearer. The whole sheet is 6.5 instructions a pixel, nearly all of it the black fill; a frame of play repaints two to five boxes of about 15 x 15 px.

**In time.** [Night Shift](internals.md#night-shift)'s scan costs 9 to 20 instructions a pixel and a full screen of it takes 2 to 3 ms on a Q2, which is 1.3 to 1.9 ns an instruction; 2 ns is used here, on the safe side. The demo's dearest frame is then 0.12 ms of the 16.67 ms a refresh allows, and a whole-sheet paint 1.4 ms. For scale, a Cover Flow frame is bounded at 6.45 million payload instructions (`test/patch.py`). ponytail: instructions are not time (cache misses on a 480 KB buffer, the other core's work); the figure is an estimate until a Q2 times it, and the bounds are in instructions because those can be tested.

### In the emulator

`q2-emu` runs the same `demo` under QEMU; its shim answers `FBIO_WAITFORVSYNC` with a 16 ms sleep and counts every page flip. A capture of the demo scene playing (`design/games/capture.py`, which records each flip's time and frame; the video is `design/games/engine-demo.mp4`):

| Capture                      | Flips a second | Gap between flips: median | 95th | 99th | Longest | Over 34 ms |
| ---------------------------- | -------------- | ------------------------- | ---- | ---- | ------- | ---------- |
| 6 s, the ball alone          | 58.3           | 17.0 ms                   | 18.1 | 20.1 | 33.7 ms | 0          |
| 10 s, the wheel and a finger | 58.6           | 16.9 ms                   | 17.9 | 20.5 | 44.2 ms | 1          |

The shim's sleep is 16 ms plus the frame's work, so about 58 flips a second is the emulator's ceiling, not the engine's: a median gap of 17 ms means the loop painted at every sync the shim gave it. The longer gaps, one of them 44 ms, came with the host busy (its load average was about 5, other builds running beside the capture); nothing here tells them apart from a slow frame of demo's, so they are stated, not explained away. A gap is whole steps to the engine (25 ms or more is two), so the ball's place stays true to time; nothing drifts.

### Measuring

- MIPS: `python3 test/patch.py BUILD` prints `Game engine on MIPS: ...`. A new game adds its own scripted second there with its own bounds.
- Emulator: `python3 capture.py EMU_DIR SECONDS OUT.mp4` beside a running emulator copy, with the game on screen.
- Host: `python3 -m pytest test/fw/test_engine.py` (the loop's steps for each gap, input, rects, drawing, saves, the demo).

## API

`patch/engine.h` is the reference; this is the shape.

```c
struct eng_game {
    const char *name;
    unsigned size, flags;                                 /* state bytes, zeroed; ENG_RAW, ENG_STILL, ENG_FULL */
    void (*init)(void *state, int h);                     /* h: the sheet's height */
    int (*step)(void *state, const struct eng_input *in); /* 1/60 s; 1 while something moves */
    void (*draw)(const void *state, struct eng_surface *s);
    void (*pause)(void *state);                           /* may be 0 */
};
```

A game is one such record, listed in `eng_games[]` (`patch/engine.c`) before `eng_demo`. `eng_count` is what Games lists; the demo is counted only in a `--dev` build with `[Q2POD] ENGINEDEMO=1` in `config.ini`, and a release build leaves it out of `eng_games[]` (`#if Q2POD_DEV`), so none of `engine_demo.c` is linked.

### Input

`struct eng_input`, one a step. A frame's edges and travel go to its first step; what is held stays.

| Field                         | Meaning                                                                                                                                                                               |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `held`, `pressed`, `released` | bits `ENG_CENTRE`, `ENG_PLAY`, `ENG_PREV`, `ENG_NEXT`, `ENG_TOUCH`. A press comes from `ringnav_keydown` (`games_keydown`), so a held button is known and stock makes no click for it; a Centre held as long as play wants never opens stock's Shut Down? or a song menu |
| `ticks`                       | the wheel's detents, clockwise positive (the wheel's sensitivity setting applies, as in a list)                                                                                       |
| `fast`                        | the same with each tick worth 1 to `ENG_ACCEL_MAX` (10) by the wheel's speed: the volume's curve ([Wheel volume](internals.md#wheel-volume)), Rockbox's `(speed / 270)^4`             |
| `wheel`                       | with `ENG_RAW`: raw travel, 200 a turn, clockwise positive, read from the wheel's own thread (`wheel_travel`); no ticks then                                                          |
| `tx`, `ty`                    | the finger on the sheet while `ENG_TOUCH` is held or just released                                                                                                                    |

Return never reaches a game. A game that sets neither flag gets ticks and runs its timer always.

### Drawing

`draw` gets a `struct eng_surface`: the screen's pixels, the sheet's origin, and the rows and columns of this paint. The sheet starts under the status row, `h` rows of it (262 to 290 by theme); a game flagged `ENG_FULL` gets the whole screen instead, 375 x 320 over the status row (Games moves its page and sheet over the status row for it: [Full screen](#full-screen)), so its `h` is 320 and its row y is the screen's. It paints its whole scene, background first; every call clips, so the cost is the changed part's. Coordinates are the sheet's, colors `0xRRGGBB` as they reach the screen (Light Mode does not flip them; Night Shift still warms them, as it reads every pixel written).

| Call           | Draws                                                                                          |
| -------------- | ---------------------------------------------------------------------------------------------- |
| `eng_fill`     | a box, solid                                                                                   |
| `eng_disc`     | a disc with a smoothed edge, its center and radius in 16.16: it moves by sixteenths of a pixel |
| `eng_round`    | a box with round corners, smoothed                                                             |
| `eng_text`     | ASCII in the theme's face through stock's canvas (left, centered or right); returns its width  |
| `eng_inset(y)` | not a drawing: the columns the glass's 80 px corners hide at each end of the sheet's row `y`   |
| `eng_clip`     | not a drawing: the part of a box inside this paint, for a game's own blits (Pop Stall's, Cabin Solitaire's, Ember Garden's) |

A buffer that is not stock's 375 x 320 BGRA8888 `lcd_mem` (a window animation's snapshot of another layout) is left as stock drew it.

### Full screen

A game with `ENG_FULL` has the whole 375 x 320 screen: while it is open Games moves its page over the status row's place and makes the sheet 375 x 320 before `eng_open`, so `init`'s `h` is 320, the sheet's rows are the screen's and `eng_inset` covers the glass's top corners too; the list puts the page back under the status row (`full_screen` in `patch/games.c`). The status row is stock's `system_bar`, a window of its own over every page, so it cannot be painted under: Games hides it while the game runs and shows it while the game is held (the screen off, another window on top, Return's menu), with its clock and battery, setting it only when that changes (`bar_shown`). All five games set the flag.

`ENG_OWN_PAUSE` is for a game that draws its own held look (Pop Stall's sign, from its `pause` call to its next step): while it is held Games draws no "Paused" pop-up over it, and `eng_paint` leaves the sheet's first `ENG_BAR` (30) rows to the status row, where its caption, clock and glyphs stand (centred on y 23, [oled-design](oled-design.md#status-row)). The others' held looks are drawn whole under the status row's window, with the pop-up over them. Return's Continue / Quit is Games' pop-up over every game, dimming the whole sheet.

`eng_state_of(game)` is that game's state while it is the one open, running or held, else 0: what a game's own timer or a hook outside its `step` reads to know whether it is still open (Caller Ten's `ct_watch`, its `callerten_sound`).

### Sound

`eng_sfx(ENG_SFX_TICK | ENG_SFX_TAP | ENG_SFX_ALERT)` plays one of the Clicker's three sounds by the Clicker's route (`clicker_route`): q2player's under Headphones or Both (mixed into the song while one plays, in silence of its own otherwise), the buzzer's by the Clicker's rule, nothing with the Clicker off. The music is never paused, ducked or reopened.

ponytail: three sounds, and the buzzer has one. Sounds of a game's own belong in q2player's table (`SOUNDS` in `player/output.c`, a pitch, a length and a decay each, made at first use): add kinds there and names to `mcl-click`, with `test/player/run.py`'s click tests extended; no payload bytes beyond the names. Not done here: it is a player change with its own tests, and one for all five games rather than per game.

### Play time

`eng_play_ms()` is the open game's play time in milliseconds: it counts while the game runs, not while it is held (Return's menu, the screen off, another window), and a rest counts at most `ENG_REST_MS` (five minutes) after the last input (a turn of the wheel, a key, a finger), so a player who walks away with the screen on stops the clock five minutes on. A game that shows a running time adds its change at each step.

An `ENG_STILL` game takes no steps at rest, so its time would stand still while the player thinks. A game flagged `ENG_CLOCK` gets a step with no input every `ENG_SECOND_MS` (1,000) while it runs and its frame timer is off (`eng_second` in `patch/engine.c`): it marks only the rect its shown time changed, and a step that starts something moving hands over to the frame timer. That timer is never on with the frame timer, is removed when the game is held, ends at a pass that finds the screen dark or another window on top, and ends `ENG_REST_MS` after the last input, so nothing wakes the UI loop for a paused, dark, closed or abandoned game. It is not `eng_live`, so the loop does not keep the frame's pace for it. Cabin Solitaire and the Evening Puzzle set it; Caller Ten's contest clock and Ember Garden run on the frame timer while their time moves. The pass also runs at rest outside play (a start board, the levels) until five minutes after the last input, a step that changes nothing.

### Saves

`eng_load(name, buf, size, magic)` and `eng_save`: the file is `/mnt/data/game-NAME`, its first word the magic, its last the FNV-1a of the rest (`games_seal`, `games_ok`), written to `NAME.tmp`, flushed, `fsync`ed and renamed over (`blob_io`). A power loss leaves the old file or the new one; a torn, foreign or missing file reads as no save, the buffer zeroed. The write waits on flash, so it belongs in `pause` or at a game's end, never in a frame of play. A failed write toasts "Couldn't save".

### Fixed point

`fx` is 16.16: `FX()`, `FX_INT`, `fx_mul` (a 64-bit product, one `mult` on MIPS), `fx_div` (32-bit, exact to 8 fraction bits, for |a| under 128). `eng_sin`, `eng_cos`, `eng_atan2` (1024 a turn) and `eng_sqrt` are Vortex's tables. The X2000 has an FPU and the payload uses `float` where stock's vector canvas wants it, but a game's `step` and `draw` stay in integers: results are then the same on the host tests, under Unicorn and on the Q2, and a test can assert a ball's place exactly. `eng_rng(&seed)` is the games' random numbers, xorshift32 on a seed of the game's own, inline in `engine.h`: the same on the host, under Unicorn and on the Q2, so a seed makes the same level, deal or puzzle everywhere (Pop Stall's levels, the Evening Puzzle's generator, Ember Garden's embers).

### Full screen

A game with `ENG_FULL` has the whole panel, 375 x 320, its sheet's height 320: `show` in `patch/games.c` moves its sheet over the status row, and `bar_over` hides the system bar (its own window, over every page) while the game runs and shows it again while the game is paused, its clock and battery over the game, or gone. Everything a player must read still keeps `eng_inset(y)` in from each end of its row.

## The demo scene

`patch/engine_demo.c`: a ball (a 6 px `eng_disc` at 2.25 and 2.5 px a step, so its edge moves by parts of a pixel) bouncing in a field, a paddle the raw wheel moves 2 px a position, a finger places and Previous and Next push; Center changes the speed of the next serve, Play/Pause leaves (`eng_quit`), a paddle hit clicks and counts, a miss beeps and serves again, and the best count is saved at a pause (`/mnt/data/game-demo`). A frame marks the ball's old and new box, and the paddle's when it moved: 2 to 5 rects of about 15 x 15 px.

To see it: a `--dev` build, `ENGINEDEMO=1` under `[Q2POD]` in `/mnt/data/config.ini`, then Library > Games > Engine Demo.

## Budgets

**The payload** may hold 1,572,864 bytes of code and constants (1,048,576 when this was measured). With the engine and its demo, `patch_bytes` is 982,392 (build `--dev --new-player`), so 66,184 bytes are free. The engine is 5.9 KB of code and constants (`engine.o`), the demo 1.7 KB.

| Game (see [Games](#games)) | Payload bytes (measured) | Heap (`size`)              | A frame, worst (instructions) | Whole sheet |
| -------------------------- | ------------------------ | -------------------------- | ----------------------------- | ----------- |
| Pop Stall                  | POPBYTES (of 28 KB)      | 252,700, its art read in   | 600,000                       | 2,000,000   |
| Cabin Solitaire            | 32,192 (of 28 KB)        | 210,652, its art read in   | 1,250,000 (its ponytail)      | 2,000,000   |
| Evening Puzzle             | 28,640 (of 28 KB)        | 23,888, its masks unpacked | 600,000                       | 2,000,000   |
| Caller Ten                 | CTBYTES (of 28 KB)       | about 216 KB, its art read in | 600,000                    | 2,000,000   |
| Ember Garden               | EGBYTES (of 28 KB)       | 242,444, its art read in   | 600,000                       | 2,000,000   |

- **A frame's hard limit is 2,000,000 instructions** of the payload's own (about 4 ms by the estimate above) for the step and every rect's paint together; 600,000 is what a game is held to, so stock's own painting of the same rects, the flush's turn of them onto the framebuffer and the loop's polls keep the rest of the 16.67 ms.
- **Heap** is one game's at a time, freed on leaving it. The device has little to spare next to the player; 8 KB is the most a game's own state is given, and a game with stored art up to 256 KB for that art: Cabin Solitaire's state is 210,652 bytes (its 37,856 bytes of art read in and the tables made from it), the Evening Puzzle's 23,888 (21,459 of them its masks, unpacked at its start).
- **Scratch** (131,072 bytes, about 31 KB free): the engine uses 4. A game uses none: its state is the heap's.
- **The root filesystem** (at most 75,497,472 bytes, `ROOTFS_ROOM`) is not used by the engine itself. A game's art that would not fit its payload bytes is a file there, `usr/share/q2games/<name>.bin` from `assets/games/` (`GAMES_DATA` in `tools/build.py`), read once when the game opens, never in a step or a paint: Cabin Solitaire's is 37,856 bytes.
- The older four games are out of the payload in this build (`GAME_*` in `patch/peq.h` all 0), which gave back 15,568 bytes (`patch_bytes` 1,331,960 to 1,316,392, 2026-11-22); turning them back on costs that again.

## Games

Each game built on the engine gets a subsection here: its file, rules in a paragraph, its save, and its measured frame figures. The briefs they are built from are in the emulator project's `design/games/BRIEFS.md`.

Every one is an original game in its genre. None reproduces an Apple iPod game's name, screens, art, sounds or level layouts; the briefs say what makes each its own.

### Pop Stall

`patch/game_popstall.c` (`eng_popstall`, `ENG_RAW | ENG_FULL | ENG_OWN_PAUSE`), Games' first engine row in every build: the same lattice, swept ball and launch rules, redrawn as a carnival balloon-pop stall seen over its counter and played on the whole panel ([Full screen](#full-screen)). The design is the emulator project's `design/games/balloon-fair/` (its `SPEC.md`, `STYLE.md` and element sheet); its `src/fair.py` draws every picture the game shows. A ruffled roof owns rows 0 to 56 with the HUD on it, the cork board with its balloons sits between two wooden walls, and a little trampoline slides along behind the counter (rows 291 to 320). The ball, a translucent violet spiky sensory ball, bounces off the wall faces (x 24 and 351), the beam's underside (y 56) and the trampoline's mat (y 280).

**Rules.** Seven rows of hexagon-packed balloons (red, orange, yellow, teal, blue, white, pink, 20 by 17 px apart from (37.5, 78)): a balloon pops at one hit; a double skin loses its pale skin at the first; a sandbag never pops, the ball rebounds and the bag swings; the gold star balloon (on the middle column where it can be) pops and its ring of up to six follows round from the upper left, two frames apart. Every pop or strip without a trampoline touch between them adds one to the combo, and each scores the level times the combo, the combo counted to 10 for points (the star's ring climbs it pop by pop). A level clear scores 100 times the level. A popped balloon, never one of the star's ring, drops a prize ticket one time in eight, two falling at most, at 1.5 px a step; caught on the trampoline it is WIDE (a 90 px trampoline for 20 s, its gold ends blinking white in the last 3), TRIO (two more balls from the first one's place, 30 degrees either side), GLUE (the next three catches stick to the mat until Center or 2 s), SLOW (the balls at 60 percent for 10 s, mint motes round each) or LIFE (a ball, 5 at most; past that 50 times the level). A life is lost only when the last ball in play falls behind the counter (its centre below y 302); that ends every timed ticket. Three misses end the game.

**Levels** come from `build` (four masks mirrored about the middle column, sizes from an xorshift of the seed and the level, double skins more often as the levels go, the star on the middle column where it can be), then the sandbags: none before level 3, then 2 and 2 more every two levels, 6 at most, in mirrored pairs on rows 2 to 6, never touching each other or the star (`fair.py` `build`, ported line for line except that a pair taken is marked at once, so the same pair is never taken twice). A level is clear when every balloon is gone; bags do not count. Speed, angles and the 15 degree floor are Bricks'.

**The ball** is swept, with a collision radius of 7 (the body's 6.3 and the spikes' tips at 8.5): `travel` meets the balloons within two rows and columns, the walls, the beam and the mat's top, four contacts a step at most; up to three balls each travel in turn. A trampoline touch turns the ball by where it hit (straight up in the middle, 60 degrees at the ends, the catch 7 px past each end) and resets the combo.

**Controls.** The raw wheel moves the trampoline 2 px a position; Previous and Next held, 4 px a step; a finger, to its x. Center launches from Ready, lets go of a glued ball, resumes from the pause and plays again after the end. Play/Pause does nothing.

**Screens.** All 24 of the design's (`mockups/01-ready` to `24-paused`) are drawn as it draws them. Ready shows LEVEL N (Bungee 20, cream with an ink edge) and PRESS CENTER TO LAUNCH at a level's start, nothing after a miss. Play: the score on an ink plaque at the roof's left, the combo pill in the middle from x2 (orange with COMBO from x5, gold with x10 MAX! at 10), the lives as small spiky balls on the right (a fourth and fifth slot appear as they are won). The stall reacts instead of the screen shaking: bulbs alternate, chase in threes from x5, all light at x10, for the star's second and through a level's clear, and brown out for 30 frames after a miss; the two bulbs over a beam hit flip for 6 frames; the plush prizes on the walls hop at a star, a clear, x10 and a ticket, and drop 2 px at a miss. A pop runs 12 frames (the bulging flash, the burst in the row's tint, shreds with a ring and the string dropping, the shreds falling) while its neighbours lean 1.5 px away for 4, and its points rise from it. The trampoline's mat dips where the ball lands, `fair.py` `DIP_CURVE` (4 px deep in two frames, one 1.5 px overshoot, at rest on frame 11, 183 ms) over 20 px either side, pinned at the ends, each spring as long as the mat is deep over it; the ball is drawn squashed into it for the contact frame and stretched for three after, spins through 4 stored frames in flight, and trails three soft dots. Level clear: the banner drops from the beam with one bounce, confetti comes four pieces a frame, then the next rows inflate from the top, a small disc, a bigger one, then the balloon, two rows at once. Game over: the rows dim two a frame, the bulbs go out and a giant ticket slides up from the counter with the score, the best and level (or NEW BEST!, whose badge pulses once) and PRESS CENTER TO PLAY AGAIN. Paused: the status row's band shows over the roof's top (stock's, see [Full screen](#full-screen)), the HUD steps down to y 38, one bulb in four stays lit and a wooden PAUSED sign hangs from the beam; Return's Continue / Quit comes over it.

**Art.** Read once by `init` from `usr/share/q2games/popstall/art.bin` (`tools/build.py` `GAMES_ART`; 251,552 bytes, sealed as a save is: first word `PSA1`, last the FNV-1a of the rest, so a torn or foreign file draws flat stand-ins and the game still plays) into the game's state, which makes the heap 252,700 bytes while it runs. ### Cabin Solitaire

`patch/game_solitaire.c` (`eng_solitaire`, `ENG_STILL | ENG_FULL`), Games' second engine row, after Pop Stall: Klondike on a cabin's card table, the redesign in the emulator project's `design/games/solitaire/` (its `SPEC.md`, `STYLE.md` and element sheet). Seven columns, four foundations by suit from the ace (hearts, spades, diamonds, clubs, left to right), a stock and a waste; columns build down in alternate colours and only a king takes an empty one; draw one or three, unlimited passes (the waste turned back over in order). A card is `suit * 13 + rank` with `UP` when face up in a column; the state is the piles and the record together (`struct record`), so a save is the game.

**The cursor and the hand.** `sources` lists every place with somewhere to go, in the wheel's order: the waste, the foundations, then each column's face-up runs from the deepest to its top card; the wheel walks only those, so an illegal move cannot be chosen and there is no error state. Center picks the place up: the card (or run) lifts and hovers over the best destination (`dests`: home first, then the longest column it builds on, then an empty column; a king alone in its column has nowhere new), the others outlined in gold where it would land, the hovered one brighter. The wheel moves the hover, Center drops, Previous puts it back. With nothing to move and nothing in the stock or the waste that could, the slip says "No moves. Prev: undo".

**Controls.** Wheel: the next place, or the next destination with a card in hand. Center: pick up, drop (with no place to pick, it draws). Play/Pause: draw, or the waste back to the stock; once every card is face up and the stock and waste are empty, the auto-finish sends everything home one card every 4 frames (Center or Play again sends the rest at once). Previous: undo, from a 64-move ring (`apply` and `unapply` leave the state byte for byte as it was), or put the hand back. Next: the cursor's card (or the hand) home, if it can go. A finger: the stock draws, a card that can move is picked up, a legal place takes the hand and anywhere else puts it back.

**Screens.** The start board (Deal: Winnable or Random; Draw: One card or Three cards; Resume, with a game in progress; wins, best time and fewest moves under it) is where the game opens; the wheel moves the gold marker, Center changes the row or resumes, Play deals. The deal flies a card from the stock every 2 frames, each a 6-frame glide on a 10 px arc, the last of each column turning as it lands. A move glides 8 frames (ease-out cubic); a card turned narrows and widens over 6; a card home flashes gold for 6 frames with 8 sparks flying out; an undo glides back with "Undo: N moves" on the slip. The win lights the four kings in turn, 6 frames apart, then shows the board ("Well played": time, best, moves, wins) with gold motes beside it; a new best's tag grows to 1.15 and settles in 10. The design drops the board in 14 frames and lets the motes drift: a frame of that drop measured 1,803,626 instructions (the board's whole box each frame), so the board shows at once and the motes stand still. The pause is the engine's (Games' pop-up, the system bar's clock and battery shown over the table), not the design's own board.

**The table.** Felt from a 64 x 64 fibre tile and a 94 x 80 map of 4 px shade cells (wear, the darker edge, two stains), each pixel a lookup into a colour table per shade level: the design's felt with its shade stepped per cell rather than smoothed. Cards are a body (the 1 px warm edge and the face, their corners from two 5 x 5 tables) with a 2 px drop shadow and the contact shade over the top edge, both drawn only where the card does not cover them; their pieces (indexes, pips, the court, the back) are masks and small palette images. Every rounded box (shadows, gold edges, outlines, the rail, the boards) is one routine, `rbox`, from constant tables of layers (`layers`); a card's five looks (at rest, raised in a run, under the cursor, home, in the hand) are made once when the game opens (`looks`: each look's layers over black and over white give, per pixel, how much of what is under shows and what they add) and drawn as two runs a row (`deco`). The felt is left out under what is painted opaque over it (`covers`: the rail, a column at rest, a top-row card, a board), and a step's changed rects are joined where they overlap (`mark`). A column fans 7 px a face-down card and 17 a face-up one, closing to 5 then 3 and to 11 at the least only when it must (`fan`, SPEC.md's rule), so the longest pile there can be (six face down under a king to an ace, column 7) ends at y 296, above the rail; each card is drawn only down to where the next covers it. The design's queen and jack hung under the baseline, cut at an 11 px fan, so the index art has a queen whose tail and a jack whose hook sit above the next card's edge. The last column is at x 309 (the design's 310), so no shadow or gold edge reaches under the glass's corner.

**Art.** One file, `assets/games/solitaire.bin` (installed as `/usr/share/q2games/solitaire.bin`, 37,856 bytes, sealed as a save is), read whole once in `init` into the state: 181 entries of 4-bit masks and 16-colour palette images (each row from a byte's start), the felt's tile, map and colour table, and per text style a table of glyphs and advances. It is written by the design's `src/export.py`, which renders each piece with the mockups' own code (`cards.py`), and its layout is `patch/game_solitaire_art.h`. Type is Libre Baskerville (indexes, labels, figures) and Playfair Display (titles), as glyph masks of the sizes and letters drawn ([third-party](third-party.md#artwork)). Without the file (or with a torn one) the sheet is a flat felt saying the art is missing; the game's state and save are kept.

**Winnable deals.** A deal is a seed: an xorshift of it shuffles the deck (Fisher and Yates), the columns are dealt row by row. Winnable deals take a seed from `sol_seeds` (`patch/game_solitaire_seeds.h`, 256 of them, 512 bytes), each one the test tree's solver won in draw three and in draw one (`test/fw/solitaire_solver.c`, a depth-first search with a visited set bounded at 200,000 states, written out by `test/fw/solitaire_solver.py --write`); random deals take any seed. `test_game_solitaire.py` wins a sample of the table again and plays each win through the game's own moves.

**Time.** The slip's time is the engine's play time ([Play time](#play-time)) added at each step of play: it runs a second at a time while the player thinks (`ENG_CLOCK`), repainting only its figure (x 205 to 281 on the rail), stops while the game is held or the screen is dark, and stands five minutes after the last input if the player walks away with the screen on. A new deal starts it over.

**Sound** is the Clicker's three: a tick for the cursor, a hover and a draw (three for a recycle), a tap for a pick-up and a drop (two when a card turns), the alert once when nothing can move, ticks for the kings, two taps for a new best. The SPEC's table of 23 sounds of its own (a rising scale for cards home) needs the q2player change of [Sound](#sound).

**Save:** `/mnt/data/game-solitaire`, `CCS1`: the game in progress, the start board's choices and the record (wins, games played, best time, fewest moves), written on the step after every tenth move once nothing glides, at the game's end, and at a pause when changed. A save is read only if every card is in it once, face-down cards lie under face-up ones in each column and the lengths and record are sane. Games' older Solitaire keeps its own file, `/mnt/data/ringnav-solitaire`, unread while it is not built.

**Frames.** Measured on build `--dev` (`test/patch.py`'s section), the whole screen (`ENG_FULL`):

### Evening Puzzle

`patch/game_sudoku.c` (`eng_sudoku`, `ENG_STILL`, `ENG_FULL`), Games' third engine row: Sudoku drawn as "The Evening Puzzle", the puzzle page of an evening paper over the whole screen ([Full screen](#full-screen)), from the design in the emulator project's `design/games/sudoku/` (`SPEC.md`, `STYLE.md`, the element sheet, layout B). Standard 9 x 9 Sudoku, every puzzle made on the Q2 with exactly one solution, at one of three levels:

| Level  | Emptied while                                                          | Stops at | Its last test                         |
| ------ | ---------------------------------------------------------------------- | -------- | ------------------------------------- |
| Gentle | naked singles (a cell with one digit left) alone still solve it        | 36 clues | none                                  |
| Steady | singles, naked and hidden (a digit with one place in a unit), solve it | 30 clues | naked singles alone must not solve it |
| Sharp  | a solver that counts solutions, stopping at 2, finds exactly 1         | 24 clues | singles alone must not solve it       |

**The generator** fills an empty grid by randomized backtracking (`sv_search` with a seed: the cell with fewest digits left next, its digits in a random order), shuffles the 41 symmetric pairs of cells (`i` and `80 - i`, the centre alone), and empties them in turn, putting a pair back when the level's test fails, until the level's clue count is reached or no pair is left. A puzzle that singles solve is unique (each placement is forced), so Gentle and Steady need no count; Sharp runs singles first, which leave the solutions as they were, and counts to two (`sv_search`, lowest digit first) from where they stopped. A puzzle that fails its level's last test is thrown away for a fresh grid (`S_TRIES`, `S_LATE`): after 9 grids, or once the puzzle has taken 135 slices of work, the last is kept whatever it is (unique, but perhaps solvable by singles). All of it is one resumable state machine (`gen_run`) with the search's stack a fixed array in the state: a step does `S_WORK` (7,200) units of work, each about 15 and at most about 20 payload instructions on MIPS, so no frame is late, and a sliced run makes the same puzzle as an unsliced one from the same seed. Meanwhile the running head's rule in the left margin fills from the foot (the pairs tried, of 41) under a card that says the puzzle is being set.

**Entry.** The wheel moves the cursor through the cells in reading order (`fast`, so a quick turn crosses the grid); Previous and Next jump a box, keeping the place in the box. Centre on a cell that is not a clue opens the dial: a sticky note 122 px square in the 4 x 4 block of cells that shares neither the cursor's row nor its column (centred at x 106 or 269, y 78 or 242), the nine digits round a pen ring, 1 at the top. Digits the cell's row, column and box clues already hold are struck and skipped by the wheel (`ticks`, one digit a detent); the dial opens on the cell's entry, else the last digit placed, else the first it can take. Centre writes the picked digit in pen and puts the dial away; Previous or Next puts it away with nothing written; Play/Pause switches the dial between pen and pencil (the hub's digit turns graphite over NOTE), and in pencil Centre notes or un-notes the digit with the dial left open. The pencil stays until Play/Pause on the dial again. A digit written leaves the notes of its row, column and box. With the dial away, Play/Pause clears the cell's entry, then its notes. A finger on a cell moves the cursor there and opens its dial; on a dial digit it writes or notes it; off the note it puts the dial away. Return is the engine's pause menu; Quit and the game again show the levels, where Play/Pause continues the unfinished puzzle and Centre makes a new one.

**The dial offers the clues' digits only, not the entries':** an entry is the player's, and may be wrong, so two entries may clash; that is what the red is for. A clash with a clue cannot be placed from the dial.

**The page.** The grid fills the height: 33 px cells from x 39, y 12, 2 px box rules and 1 px cell rules, the left margin the paper's running head set sideways with its rule, the right margin a tally of the digits (struck once the board holds nine of one), the time in pen, the level in type and the slips in red. Clues are printed (Libre Baskerville Bold), entries handwritten in blue pen (Patrick Hand) half a pixel off centre, notes small graphite digits in their ninth of the cell; the cursor is a yellow highlighter in a blue pen box, its row, column and box take a pale wash and every other cell holding its digit a blue one. A digit placed that clashes is the slip: written red and circled, what it clashes with (a clue, or the entry placed before it) underlined twice in red, and counted (`slips`, kept in the save). A unit filled with nine different digits (never checked against the solution) takes a green highlighter wave, a cell each `S_WAVE` (3) steps. Finishing stamps the page SOLVED in red and shows the time, the best or "new best!" and the level on a sticky note. A pause lays a desk blotter over the grid, so it is not free thinking time. The levels page is the paper's puzzle column: the title, a card a level with a thumbnail of its clue pattern, its clue count and its best, the chosen one in highlighter and pen, and the unfinished puzzle on a strip under them.

**The art.** The digits and words are masks drawn from the four fonts the design names (Patrick Hand, Libre Baskerville and Playfair Display under the OFL, Special Elite under Apache-2.0; [third-party](third-party.md#artwork)) at only the sizes and glyphs the page uses, by `tools/game_art.py` into `patch/game_sudoku_art.inc`: 8,544 bytes, packed in nibbles of 4-bit alpha with runs. At the game's start `unpack` reads them once into the state as rows of inked spans (21,459 bytes), so a paint walks ink alone, and `stamp` blends an edge pixel from the fourteen blends of the ground it last met. The paper's grain is a few flecks a row from a hash of the row, so a part repaints as it was; rings and strokes are smoothed by distance (`ring`, `line`); round corners come from a small table (`corner`). All of these are the game's own, next to the engine's `eng_fill` and `eng_disc`.

**What a step paints.** Each cell's look is a key (`look`: its washes, its digit and the digit's kind, an underline, its notes), kept from the last paint; a step recomputes the 81 and marks each row's changed span (2 px wider for the cursor's box), the margin when its second, tally or slips change, and the dial's hub and two digits when it turns. **The wash follows the cursor a stage a frame:** the old twins off (with the cursor's box), then the old peers, then the new peers on, then their twins (`wash`, `wcur`), and none while the dial's note is open or on the frame that puts it away (`busy`); a digit placed brings its twins a frame after the note goes. So no frame repaints two washes or a wash with the note: a cursor's move repainting every row measured 1,232,944 instructions as one frame and is four of 421,000 at most. Nothing blinks; a frame is painted only after input or while something moves.

**The clock** is the engine's play time ([Play time](#play-time)) in steps of play: it runs a second at a time while the player thinks (`ENG_CLOCK`), repainting only the margin's time line (rows 205 to 221; the whole margin when the tally or the slips change), stops while the puzzle is held or the screen is dark, and stands five minutes after the last input if the player walks away with the screen on. The levels and the setting do not count.

**Sound:** a tap for a digit placed, the alert for a slip, a tick for a note, three taps six steps apart for a finished puzzle. ponytail: the design's ten sounds (a pen's tap, a pencil's tick, rising notes for a finished unit, the stamp) need q2player's `SOUNDS` table ([Sound](#sound)); until then these are the Clicker's three.

**Save:** `/mnt/data/game-sudoku`, `SDK1`, 436 bytes: the clues, the solution, the entries, the notes (9 bits a cell), the cursor, the level, the slips, the elapsed steps, whether it is finished, and each level's best. Written at a pause when anything changed since the last write, and when a puzzle is finished. On load it is checked whole before use: the solution a full grid, each clue the solution's digit, no entry on a clue, entries 0 to 9, notes 9 bits, the cursor on the grid, times under 99 hours; anything else reads as no save. The older built-in Sudoku's `/mnt/data/ringnav-sudoku` (`games.c`, left out of this build) is another file, not read or touched.

**Against the design.** Built on layout B as drawn, with notes as digits, the peer wash and the pause's blotter (the design's own choices where `BRIEFS.md` differed). Simplified: the levels' unfinished strip names the level, not a puzzle number (puzzles are made, not numbered), and has no paper clip; the setting card is in type alone and the clues do not print while the puzzle is set; the dial's note appears and goes, and a digit lands, without the design's scaling, peel and ink flecks; a finished unit's wave is a cell every three frames with no pen tick in the margin; the stamp has no page shake; the Reduce Motion, Mark Mistakes, Peer Wash and Large Notes switches of the start screen are not built; the pause is the engine's menu over the blotter; an empty cursor cell washes no twins (the play mockup's 5s round one), as that cost a frame over the budget and payload bytes past it. Measured against the @1x mockups in the emulator, the main elements' boxes are within 2 px but two: the slip in the margin is 3 px wider (the hand set's 12.5 px digits, not the 11 px the mockup writes it in) and the stamp's frame reaches 4 px further right.

**Frames.** Measured on build `--dev`, on the 320 px full-screen sheet (`test/patch.py`, payload instructions on MIPS):

| What                                                                                 | Instructions | Bound     |
| ------------------------------------------------------------------------------------ | ------------ | --------- |
| A generator slice, the dearest of three Sharp puzzles and a Gentle one               | 142,516      | 150,000   |
| That frame with its progress rule painted                                            | 197,444      | 220,000   |

So the slowest of those Sharp puzzles takes 1.3 s at 60 frames a second, within the brief's 3 s; the host test makes 200 a level and bounds every one at 180 frames. ### Caller Ten

`patch/game_callerten.c` (`eng_callerten`, `ENG_STILL | ENG_FULL`), Games' fourth engine row, after the Evening Puzzle: a radio call-in contest on the user's own library, the redesign of the music quiz brief (the design is the emulator project's `design/games/guess-the-song/`, its SPEC.md, STYLE.md and element sheet). An evening side table fills the screen: a wooden table radio plays a clip, a red rotary phone is the control and a notepad holds the four answers. The radio says what the game is doing (ON AIR, STAND BY, one line on its glass), ten clock lamps count the seconds, the dial and the pad's chosen row always show the same number.

**Rules.** Tune the radio to one of three contests (the needle slides between three stations; the pad lists them with their bests): Titles ("Name the song"), Artists ("Who is playing?") and Deep cuts (titles of songs played once or never: the [play counts](internals.md#play-counts) of two or more left out). A round plays a clip from 30 to 60 percent into its song; the round's clock starts when the player answers that the clip is heard, not when it was asked for, and its points fall from 100 to 10 over 10 s (`100 - 3 at / 20` steps, the last lamp staying lit; there is no timeout). Ten callers make a contest, three wrong answers end it early ("LINES ARE CLOSED"). A wrong answer is struck in red and the right one shown green with a check; three right in a row light "HOT LINE x3" on the glass and swell ON AIR's halo once, with no score of its own. The summary lists the songs missed: Center on one plays it in full from its folder (`songs_open`) and leaves for Now Playing; Play/Pause tunes in again.

**Controls.** The wheel tunes, dials 1 to 4 (it stops at each end, no wrap) or picks a missed song; Center calls in, places the call, plays a missed song; Play/Pause replays the clip from its start once a caller (the replay lamp goes dark), and on the summary starts a new contest; a finger on a row answers or picks it. Previous and Next do nothing. Return is Games' menu.

**The library.** A worker thread (`pick_worker`, as slideshow.c's shape) reads songs in a random order from `main.songtable` alone, through `era_sql` (the library scope applies; naming the table in full keeps a server's `cat.servertable` out, and a row of a server's at a card path, `catalogue_path`, is skipped too), with `MUSIC_WHERE` (no audiobooks, podcasts or `.m4b`), no CUE tracks and a title (Artists: an artist too), keeping 64. The first 26 are checked as answers on the worker: the file there (`access`) and at least 40 s long by TagLib (`seconds`, durations.c's way), 13 kept: ten callers and three spares. A contest needs 12 songs and four that read differently ("A contest needs 12 songs", or 4 artists, on the pad under NO SIGNAL; no playable answer says so too). Each round deals its three decoys on the UI thread from the 64, those of the answer's genre and decade first, never two that read the same (ASCII case folded). One round ahead a small thread looks whether the next answer's file is still there (`look_ahead`): a song gone mid-game is passed over before its round, and a clip the player answers `error` for, or that is not heard in 5 s, is passed over at once for a spare, the caller's number kept; with no spare left the contest ends short. The worker's rows are a block of its own (`struct pick`, refcounted), read by the game only after its `done`, so a game left while it runs frees nothing it uses.

**Playback.** The game owns the sound while a contest runs. At its start `take` stops Spotify and a radio and holds the Library's song where it was (`now_hold`, as a video does, [Now Playing source](internals.md#now-playing-source)), noting whether it played. Each clip goes straight to q2player over demo's player socket (`{mcl-stop}{set-songurl\PATH|ss=S|512|20|0|17|90}`, demo's own fields), never through the queue, so no play count, scrobble, resume place, Up Next or car title moves; the jack is readied as stock's start readies it (`dac_take`) and the DAC kept on. The game asks `{player-status\request}` every 6 steps while a clip is cued and reads the answer from demo's reply list (`mcl_reply_take_by_key`, stock's, never waiting); `playing` is the player's state once the clip is heard, which starts the clock. The reveal pauses the clip; a pause of the game (the menu, the screen off) pauses it and Continue plays it on. While the game holds the sound `addon_game_audio` says so (`callerten_sound`), so stock's player starts nothing over it ([internals: card games](internals.md#card-apps)). Games frees a game's state at its close without calling it, so `pause` arms a watch (`ct_watch`, every 100 ms, `eng_state_of`): once the game is gone it stops the clip and gives the Library's song back as it was, playing on from its place (`now_take_back`) or loaded paused there (`now_release`), a stopped one left stopped; it also frees the art and the worker's rows.

**Screens.** Tune-in, stand by (the worker; STAND BY lit, three lamps chasing), a round (the question on the glass; ON AIR, the rings and the ten lamps once heard), the call (the handset lifts 27 px and tilts 13 degrees over 6 frames with a back-out, the clip plays on 20 frames), the reveal (60 frames: the wash in three steps, the check drawn in 6, the strike in 8, the points and the score counting up in 20), the summary (the wide sheet comes up from under the screen's edge over 14 frames with a 5 px overshoot, revealed by a rising edge rather than moved; then the score counts up in 40 and NEW BEST shows) and NO SIGNAL. A title is drawn at 17 px and tried at 16, 15 and 14 before it is cut with "..." (`fit_text`); the chosen row, cut, scrolls its whole title (40 steps still, 1 px every 2 steps, 40 still, back), and the right row on the reveal once through. Under Reduce Motion (`motion_reduced`) the dial does not spring, the handset is up at once, the rings stand still and the summary is there at once. The screen is kept lit through a round (`eng_awake` each second), as a video keeps it.

**Art.** `assets/games/callerten.bin` (`usr/share/q2games/callerten.bin`, 192,228 bytes), made with `patch/game_callerten_art.h` by the design's `src/export.py` from the same drawing code as the mockups: one 256-colour palette (median cut refined by k-means over the pictures' own pixels), 100 pictures each a rectangle at its place cut from a whole render of the scene in that state (the room with the radio, phone and pad at rest; ON AIR's three states, the replay lamp, the rings' three frames, each lamp lit amber and red, the dial on each number and its three turn steps, the hub's answer, the handset's five poses and its cord's, the pad's sheets, rows, badges, check, strike boxes, the summary's sheet and rows), row run-length coded with row offsets, and glyph masks of Righteous (15 and 14 px) and Bungee (18, 21 and 36 px digits) for the type the game sets at run time (OFL, `assets/games/callerten-fonts.txt`, [third-party](third-party.md#artwork)). The glass's corners are black in the art. It is read whole at `init` and checked by its size and seal (`games_ok`); a missing or damaged file toasts "Caller Ten's pictures are missing" and goes back to the list. `blit` decodes a picture's rows within the part being painted, skipping where a sheet drawn over it covers the room. The library's titles and artists go through stock's canvas in the theme's face or the fallback that has the script (`theme_face`, `draw_centred`), so every script the firmware draws shows.

**Sound** is the Clicker's three (the SPEC's tones are a q2player change for all games, [Sound](#sound)): a tick at each detent, a tap before the clip starts (never over it), three taps after a right answer and two ticks more on a streak, the alert for a wrong one, a tap at the end and three for a new best.

**Save:** `/mnt/data/game-callerten`, `CTN1`: the best score of each contest and the contests played, written at a contest's end. A best over 1,000 or a count over 99,999,999 reads as none.

**Frames.** A frame of play marks each thing that changed once (`flush`: the glass, ON AIR, the replay lamp, the rings, the lamps, the knob, the handset, the dial, the band, the score line, the rows, joined where they touch), so it never passes the engine's eight rects. The reveal paints the rows at once and the glass, the hub, the band and the score in the next two frames, and the score counts up after the summary's sheet is up, so no frame carries all of them. ### Ember Garden

`patch/game_embergarden.c` (`eng_embergarden`, `ENG_RAW | ENG_FULL`), Games' fifth engine row, after Caller Ten: the turret shooter of the briefs, redrawn as a world. A far volcano's ash cloud rains embers on a kitchen garden, and a brass impact sprinkler on the lawn (pivot 187.5, 270) puts them out with spurts of water. Embers fall from under the canopy (y 40, x 30 to 345) on a sine sway of 18 px over 180 steps, small, medium and cinder (radius 3, 4.6 and 7), worth 1, 2 and 3; a cinder hit cracks into two small embers that fly apart at 1.6 px a step, slowing, and the embers and spurts hold for 3 steps. Only a spurt's lead drop puts an ember out (a disc of 4.5 px against the ember's, by squared distances in 1/16 px); its trail of four drops sags behind it and is drawn only. An ember that reaches the ground (y 258) sets the nearest growing bed on its side of the sprinkler alight: it catches 8 steps later, burns 90 and stays charred. Four beds a side: the third lost frames the side's last bed ("LAST BED", blinking 60 steps on and 30 off), the fourth ends the game. A wave of N is 6 + 2N embers to 40, one every 70 - 4N steps (18 at least), falling at 0.5 + 0.06 (N - 1) px a step to 2.2; every tenth is a lull of five slow cinders worth double ("LULL x2"). At most 12 embers fall at once, 6 of them cinders, three spurts fly and three steam puffs show. The game's own xorshift, seeded at a new game, makes the waves, so one seed plays the same.

**The scene** is the art file's, `usr/share/q2games/embergarden.bin` in the root filesystem (`assets/games/embergarden.bin`, made by the emulator project's `design/games/sky-defense/src/export.py` from the design's own drawing code and Baloo 2; `patch/game_embergarden_art.h` is its table), read whole into the game's state by `init` and never again. The scene is a byte a pixel, an index into a palette of 256 for each band of 32 rows, each entry four colours, one for each time of day (dawn, day, dusk, night): the four renders were clustered together, so a time of day is a palette and the light's turn is two palettes mixed (`palette`). The charred beds are boxes of the same indexes, copied over a bed's when it chars and the kept growing ones copied back for a new game. Over the scene, `draw` paints premultiplied sprites (embers, flames, puffs), 4-bit masks coloured as they are drawn (the lettering, the fire's glow), and discs and square-ended strokes (the spurts, the sprinkler's head, the lightning). An ember's tail leans the way it moves: the sprite's rows above its centre shift by a slope of its sway. Without the file (or with one whose size, magic or table is wrong) the game plays on a plain sky and lawn with discs for embers.

**The day.** Waves 1 and 2 are dawn, 3 to 5 day, 6 and 7 dusk, 8 to 10 night, then again. A new time of day turns over 32 passes of strips, a strip of 8 rows painted each step (40 a pass), the palette a 32nd further at each pass's start: 21 s, longer while the sky is full (below), and no frame repaints the sheet. The sprinkler, the markers' numbers and the beds' wood are lit by the same mix of the design's ambient colours (`lit`); water, embers, fire and lightning are not. Lightning strikes in the ash column after dusk and in a lull, at most once in 120 steps and only over 4 embers or fewer, never under the wave banner: a bolt with one branch, two frames bright and two dimmer.

**Controls.** The raw wheel aims 1.2 degrees a position over the arc from -170 to -10 degrees; Previous and Next held, 2 degrees a step; a finger aims at itself (level with the pivot or under it, the arc's nearer end) and sprays on its press. Center sprays, again every 12 steps while held; Center or a tap starts from the title card and replants from the result card. Play/Pause does nothing.

**Screens.** The title card (a seed packet: the best and best wave) at dawn; play, with the score and the wave on two plant markers; the wave banner ("WAVE n" in 30 px, the light's line under it: "dawn is breaking", "the sun is up", "dusk is falling", "night is here") for 45 steps, then fading over 15; the result card ("GARDEN LOST", the score, the best or a "NEW BEST" tag, the wave) dropping in over 14 steps as the scene dims to 55 percent toward the design's night tint. A `--dev` build with `[Q2POD] EMBERWAVE=N` in `config.ini` starts play at wave N in its light, to see a later wave without playing to it. Pausing is the engine's, the status row shown over the game while it is paused ([Full screen](#full-screen)).

**Sound** is the Clicker's three: a tick for a spurt, a tap for a hit and two for a cinder's crack, the alert for an ember landing, two ticks for a wave, three alerts for the garden lost.

**Save:** `/mnt/data/game-embergarden`, `EMG1`: the best score and the best wave, written at the game's end when either was beaten (and tried again at a pause if that write failed). A save with a best over 99,999,999 or a wave over 9,999 reads as none.

**Against the design** (the emulator project's `design/games/sky-defense/`), each for the frame's cost or the engine ([Frames](#frames-ember-garden) below has the measurements): the brief's 24 embers at once are 12, 6 of them cinders, and only an ember spawned while fewer than 8 fall has the design's long smoke thread (the rest a short tail, the SPEC's own fallback). A step's extras (the banner's fade, a puff's and the flames' next frames, a strike of lightning, the light's strip) are painted only while its boxes with theirs stay within 14,000 pixels (`G_BUDGET`, `extras`); one that does not fit waits for a step with room, and one puff turns a step at most. So the light's turn slows while the sky is full, and a flame or a puff can hold a frame a few steps longer. Lightning has no glow and no flash of the column, lasts four frames, and strikes only over 4 embers or fewer. The result card's words print as it lands. A flame shows 8 steps a frame. The steam, the embers' glow and the fire's glow are drawn at one strength for every time of day (the design's dusk). The critters, the volcano's pulse and the ash fall are still, the sun and moon move by the palettes' mix (each in its own place, one fading as the other comes), and the score marker does not grow on a hit. The design's pause (a dimmed scene, its own sign) is the engine's menu, and its accessibility toggles (reduce flashing, reduce motion, fixed daylight) are not built: the game's menu is the engine's. The SPEC's own sounds wait for the planned q2player table ([Sound](#sound)).

## Libraries

Looked at for vendoring. The project is GPL-3.0, so MIT, BSD, zlib, public domain and GPL-2.0-or-later code could all be taken; none is, because each need is smaller than the library that meets it.

| Need                          | Candidate                                                           | License               | Size                                                            | Verdict                                                                                                                                                                                                                                                             |
| ----------------------------- | ------------------------------------------------------------------- | --------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fixed-point maths             | [libfixmath](https://github.com/PetteriAimonen/libfixmath)          | MIT                   | Q16.16 in C; its caches are 32 KB and 80 KB unless compiled out | No. Two inline functions and Vortex's 257-entry sine and arctangent tables, already in the payload, are the whole need                                                                                                                                              |
| Physics and collision         | [Chipmunk2D](https://github.com/slembcke/Chipmunk2D)                | MIT                   | a rigid-body engine in floating point, over 100 KB compiled     | No. Far past the payload's room, and nothing here is a rigid body                                                                                                                                                                                                   |
| Collision tests only          | [cute_c2](https://github.com/RandyGaul/cute_headers)                | zlib or public domain | one header, floating point                                      | No. A disc against a disc and a disc against a box are a few integer lines each, exact and testable in fixed point                                                                                                                                                  |
| Sudoku solving and generating | [kudoku](https://github.com/attractivechaos/plb/tree/master/sudoku) | MIT                   | 190 lines of C, integers only, one `calloc` of its matrix       | No, but the nearest to a yes. It solves by exact cover; the game needs a solver that counts to two solutions and can stop and resume between frames, which is a different loop. A bitmask backtracker is under 100 lines                                            |
| Sudoku generating             | [QQWing](https://qqwing.com)                                        | GPL-2.0-or-later      | C++                                                             | No. The payload is C with no C++ runtime                                                                                                                                                                                                                            |
| Klondike solvability          | [Klondike-Solver](https://github.com/ShootMe/Klondike-Solver)       | MIT                   | C++; searches up to 5,000,000 states by default                 | Not in the firmware: that search does not fit a Q2's memory. Solvability is checked offline by a small solver in the test tree (`test/fw/solitaire_solver.c`), and the firmware carries a table of seeds it solved (512 bytes, [Cabin Solitaire](#cabin-solitaire)) |
| Sprite and shape blitting     | [olive.c](https://github.com/tsoding/olive.c)                       | MIT                   | one header                                                      | No. `eng_fill`, `eng_disc` and `eng_round` are short, clip to the rect being painted, and write the screen's own pixel format                                                                                                                                       |
| Random numbers                | [PCG](https://www.pcg-random.org)                                   | Apache-2.0 or MIT     | a few lines                                                     | No. `rand_below` (xorshift, `patch/playback.c`) is already there and is enough for deals and levels                                                                                                                                                                 |
| Whole games to port           | [Rockbox](https://www.rockbox.org)'s plugins                        | GPL-2.0-or-later      | each tied to Rockbox's plugin API and LCD model                 | No. Compatible, but a port brings the API with it, and these games are designed for this screen and wheel                                                                                                                                                           |
